What to look for

A short guide to the current Admin Center build.

Back to workspace
Current data: Bot, learning and model examples are synthetic unless a feed says otherwise. The hub is not configured; lead and coordinator panels use read-only local records; bridge status uses a read-only SSH observation. Model changes remain disabled.

Try these

  1. See what changed. Open the workspace and read “What's new” and the hub status banner. The source selector defaults to synthetic examples; selecting “Try configured read-only hub” currently shows fallback until access is configured.
  2. Inspect a bot. Check the per-game loaded-roster counts, filter by game or name, and choose “Inspect” on an entry. “Clear roster filters” restores the loaded list. Check its displayed character, level and body-kind metadata, then its linked example evidence and issues. Missing fields and actual presence remain unknown. Open “Model routing (read-only)” for one bot, or use “Show visible routing details” and “Hide visible routing details” for the filtered list; these only change display, and purpose and model controls cannot be changed. The reply source panel shows synthetic fallback and delivery evidence separately. “Clear bot selection” clears the inspector and linked views.
  3. Explore learning needs. Filter by game or status, search by topic or reason, check the per-game loaded-record coverage, and inspect a need for its phase, evidence and policy state. Open “Game learning planning checklist” to show or hide planned FFXI and SWTOR topics; the game filter applies. These are not verified gaps, and evidence, datasets and policies remain unknown. Related issues appear when explicitly linked; missing evidence is shown as unknown or not included. Toggle “Show known attention statuses only” to narrow the list to the named statuses; use “Clear learning filters” to restore it.
  4. Check game settings. The game settings card shows a stored snapshot where available. Its time and source matter; it does not establish whether the server is online.
  5. Watch the bridge. The FFXI chat bridge card shows the unit and fault marker from a read-only observation, refreshing while the workspace is visible. An absent marker does not prove a reply was delivered.
  6. Review issues. Filter by scope or status, or search. Toggle “Show issues linked to the selected bot” after selecting a bot to show explicit links only. Scope counts cover only loaded records, not all incidents; “Clear issue filters” restores the loaded list. The FFXI bridge fault card describes historical project evidence; its current status is unknown. Coordinator decision cards link to the read-only “Needs Blizz” summary.
  7. Check lead activity. Compare the lead stall and quota summary with the timeline and nudge history. Shared quota estimates are not individual lead quota, and activity after a nudge is only a heuristic.
  8. Review the spend example. The spend card is synthetic and does not read the live ledger. Unknown budget and per-bot attribution are not zero.
  9. Follow evidence. Filter the synthetic action ledger by correlation ID. When a hub is configured and selected, the same search can request a bounded read-only hub trace without raw message bodies. A request, its result and its verification are separate; a dispatched request alone does not prove completion.

Feedback that helps

Note the section, what you clicked, what you expected, and what you saw. For a display issue, include the game or example bot and the selected data source.
