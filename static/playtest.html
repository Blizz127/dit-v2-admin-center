What would demonstrate FFXI learning?

New in this guide: the evidence checklist below explains what to look for when reviewing learning needs. It is always visible here. In the workspace, inspect an FFXI learning need and expand “FFXI learning evidence checklist (read-only)” to see these requirements and their Unknown evidence states for the selected record. Collapse it to hide the checklist. Selecting a different game shows that the FFXI checklist does not apply; clearing the learning selection clears its context. Use “Preview synthetic evidence mapping” to see independent supported, missing, conflicting and absent-evidence examples with provenance. Use “Show selected need evidence” to return to the actual loaded record; a verified task still has Unknown game assessments. The reason text distinguishes omitted light-response evidence from evidence merely reported present. These display actions make no hub request. Current game evidence is unverified. An unknown field means evidence is missing, not that a bot failed.

  • Identity: look for a verified native bot and realm, source and observation time. A matching display name does not connect an interaction actor to the roster.
  • Navigation and missions: look for the starting state, objective, native result and a later observation of progress. An accepted request or correlated trace is not completion.
  • Party behavior: look for a defined job and party scenario with observed results and failure or fallback evidence. A healthy service does not demonstrate bot behavior.
  • Memory: look for the underlying verified fact and its scope, source and time. Plausible dialogue is not evidence that an event happened.
  • Policy improvement: keep dataset provenance, policy version, validation, adoption and measured game outcomes separate. A completed learning task does not establish all of them.
